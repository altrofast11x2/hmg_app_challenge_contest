# 운행 기록 무결성 (해시 체인)

> **상태 (2026-10-27)**: 차량 앱의 해시 체인 생성과 검증(`TripLedger.verify`), 서버 저장(운행·이력·체인 머리, 체인 ID)을 구현하고 단위 테스트와 실서버로 확인했습니다. 관리자 웹의 검증 배지는 아직 구현하지 않았습니다 (M2).

## 무엇을 막는가

운행기록부의 핵심 숫자인 **주행 전/후 계기판 거리**와 **업무/비업무 분류**를 나중에 몰래 바꾸지 못하게 합니다.
- 계기판 값은 차량(Vehicle SDK)에서 읽은 원본이고, 출처를 `VEHICLE`로 표시합니다. 사람이 고쳐도 원본은 그대로 두고 수정 이력이 쌓입니다.
- 분류와 수정은 모두 이력(`trip_changes`)으로 남고, 운행 기록과 같은 체인에 들어갑니다.
- 체인을 다시 계산하면 값 변경, 중간·끝 기록 삭제, 순서 변경, 이력 없는 분류 변경을 찾아냅니다.

## 체인 구조

차 안에서는 차량마다 체인이 하나입니다. 기록은 두 종류이고, `seq` 순서로 하나의 체인을 이룹니다.

동의를 철회하거나 앱을 다시 설치하면 차 안 기록이 지워지고, 같은 차(VIN)에서 체인이 seq 1부터 새로 시작합니다. 그래서 서버에는 한 차량에 체인이 여러 개 있을 수 있습니다.
- **체인 ID = 그 체인 첫 기록(seq 1)의 해시.** 서버는 운행·이력을 (차량, 체인 ID, seq)로, 체인 머리를 (차량, 체인 ID)로 구분합니다 (`0009_chain_id.sql`).
- 해시 계산 규칙은 바뀌지 않습니다. 체인 ID는 해시에 넣지 않고, 기록이 어느 체인인지는 prevHash 연결로 확인됩니다.
- 2026-10-27 이전에 올라간 기록도 같은 규칙(그 차량의 seq 1 해시)으로 체인 ID를 채웠습니다.

| 종류 | 언제 생기나 | 체인에 들어가는 값 |
|---|---|---|
| `TRIP` | 운행이 끝날 때 (분류 버튼 또는 정차 대기 시간 경과) | 운행 ID, 시작·종료 시각, 시작·종료 계기판 거리, 계기판 출처, 시작·종료 배터리 잔량 |
| `CHANGE` | 분류하거나 값을 고칠 때. 0.3.0부터 운행을 마칠 때 운전자(`DRIVER`, "이름 · 부서")와 주행 중 음성으로 남긴 업무 내용(`WORK_NOTE`)도 운행 기록 바로 뒤에 남긴다 | 이력 ID, 운행 ID, 항목, 이전 값, 새 값, 바꾼 사람(`driver:<운전자 ID>`, 음성은 `voice:<운전자 ID>`), 사유, 시각 |

- 주소는 체인에 넣지 않습니다. 비업무 운행은 주소를 지워야 하기 때문입니다.
- 위치 성격의 수정 이력(`VISIT_NOTE`, 업무 내용 `WORK_NOTE`)은 원문 대신 `sha256:<해시>`로 체인에 묶습니다. 비업무로 바뀌어 원문을 지울 때 이 값으로 바꿔 두면 체인은 그대로 검증됩니다.
- 체인의 마지막 위치(`chain_heads`)를 따로 저장해 끝부분을 지운 것도 찾아냅니다.

## 계산 규칙 (웹에서 다시 계산할 때 그대로 따라야 함)

```
hash = SHA-256( prevHash + "\n" + canonical )   // UTF-8, 결과는 소문자 16진수 64자
첫 기록의 prevHash = "0" × 64
canonical = 아래 순서의 "key=value"를 "\n"으로 이은 문자열
  - null은 빈 문자열
  - 값 안의 "\" → "\\", 줄바꿈 → "\n" 으로 이스케이프
  - km는 소수 첫째 자리까지, 점(.) 사용 (예: 112.3)
  - 시각은 epoch 밀리초 정수
```

`TRIP` 필드 순서: `type=TRIP`, `vehicleId`, `seq`, `tripId`, `startedAt`, `endedAt`, `startOdometerKm`, `endOdometerKm`, `odometerSource`, `startSocPercent`, `endSocPercent`

`CHANGE` 필드 순서: `type=CHANGE`, `vehicleId`, `seq`, `changeId`, `tripId`, `field`, `oldValue`, `newValue`, `actor`, `reason`, `createdAt`

구현: `app/src/main/java/com/altrostudio/drivelog/data/trip/HashChain.kt`, `TripLedger.kt` · 테스트: `app/src/test/.../data/trip/`

## 한계

- 체인은 기기에서 만듭니다. 기기 DB 전체를 처음부터 다시 만들어 바꾸는 공격은 체인만으로는 막을 수 없습니다. 서버에 올라간 체인 머리와 비교하면 찾을 수 있습니다 (비교 화면은 M2).
- M1에서는 차량 앱만 체인에 기록합니다. 관리자 웹에서 고치는 기능(M2)을 만들 때 서버 쪽 기록을 어떻게 이을지 정합니다.
