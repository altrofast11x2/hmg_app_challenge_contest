# 코드 설명서: 발표·질의응답 준비용

차곡의 코드가 어떻게 짜여 있고, 기능마다 어느 파일이 무슨 일을 하는지 정리했습니다. 처음 보는 팀원이 이 문서 하나로 "이 기능은 어떻게 동작하나요?"에 답할 수 있게 쓰는 것이 목표입니다. 경로는 `app/src/main/java/com/altrostudio/drivelog/` 아래 기준입니다.

## 1. 한눈에 보기

| 덩어리 | 위치 | 하는 일 |
|---|---|---|
| 차량 앱 | `app/` | 기어를 보고 운행을 자동으로 기록하고, 정차하면 용도를 묻고, 차 안 기능(공조·시트·무드등·창문·문)을 다룬다 |
| 서버 | `backend/supabase/` | 회사별로 기록을 모은다. 표 권한(RLS)과 함수로 "자기 회사 것만" 보이게 한다 |
| 관리자 웹 | `web/` | 회사 담당자가 차별 운행기록부·업무 일지를 보고 내려받는다. 휴대폰으로 받기 페이지도 여기 있다 |

앱은 **인터넷이 없어도 혼자 동작**합니다. 기록은 먼저 차 안에 암호화해 저장하고, 회사에 연결돼 있고 인터넷이 될 때만 서버로 올립니다.

## 2. 앱의 층 나누기

```
ui/       화면 (Jetpack Compose). 보여 주고 누른 것을 ViewModel에 넘긴다
domain/   규칙 (운행 상태, 기록부 계산, 음성 대화, 차 점검). 안드로이드에 거의 기대지 않아 단위 테스트가 쉽다
data/     바깥 세상 (차량 SDK, 내비, DB, 서버, 음성 엔진). 인터페이스 뒤에 숨겨 테스트에서 가짜로 바꾼다
service/  화면이 꺼져도 기록을 계속하는 포그라운드 서비스, 부팅 시 시작, Gleo 음성 명령 수신(향후 계획용, 출품 기능에는 쓰지 않음)
AppContainer.kt  위 부품을 한곳에서 만들어 서로 연결한다 (의존성 주입 라이브러리 없이 직접)
```

설명할 때 핵심 문장: **"화면은 규칙을 모르고, 규칙은 차량 SDK를 모릅니다. 그래서 차 없이도 규칙을 테스트할 수 있습니다."**

| 폴더 | 주요 파일 |
|---|---|
| `domain/trip` | `TripStateMachine`(운행 상태 규칙), `TripRecorder`(규칙을 실제로 돌리고 저장) |
| `domain/voice` | `VoiceJournal`(정차 후 말로 기록), `SpokenTrip`(말을 용도·업무 내용으로 해석), `HelpAssistant`(도움 비서), `VoiceGuide`(소리 안내 문장) |
| `domain/cabin` | `CabinAssistant`(무드등 신호, 하차 점검, 차 상태 보기) |
| `domain/driver` | `DriverProfiles`(공용차 운전자 고르기와 맞춤 설정) |
| `domain/logbook` | `LogbookBuilder`(국세청 서식 운행기록부 계산), `LogbookCsv` |
| `data/vehicle` | `PleosVehicleDataSource`(기어·계기판·배터리 읽기), `PleosCabinControl`(공조·시트·무드등·창문·문 제어) |
| `data/voice` | `PleosSpeaker`(TextToSpeech), `PleosListener`(SpeechToText) |
| `data/trip` | Room DB 표, `TripLedger`·`HashChain`(해시 체인) |
| `data/sync` | `SyncRepository`(서버로 올리기), `SyncScheduler`(언제 올릴지, WorkManager) |
| `ui` | `DriveLogRoot`(지금 어떤 화면을 띄울지), `MainViewModel`(화면과 규칙 연결) |

## 3. 핵심 흐름

### 3-1. 운행 자동 기록: "타고 내리면 기록이 끝납니다"

1. `PleosVehicleDataSource`가 기어 값을 계속 받습니다. 기어는 Pleos Gear API가 deprecated라서 안드로이드 차량 표준 값(`GEAR_SELECTION`)을 씁니다.
2. `TripRecorder`가 기어 변화를 `TripStateMachine`에 넣습니다. 상태 기계는 **대기 → 주행 중 → 정차 → 대기** 네 가지 규칙만 압니다.
   - P에서 벗어나면(D·R·N) 운행 시작. 계기판 거리·시각·주소를 저장합니다.
   - P에 들어가면 정차. 다시 D에 넣으면 같은 운행을 이어 갑니다(잠깐 세운 경우).
   - 정차 중 용도를 고르거나 5분이 지나면 운행을 마칩니다(5분이면 미분류로).
   - 신호 대기는 기어가 D 그대로라 정차로 보지 않습니다.
3. 상태가 바뀔 때마다 **바로 DB에 저장**합니다. 시동을 끄면 앱이 갑자기 죽을 수 있어서, 다시 켜지면 진행 중인 운행을 이어 갑니다.
4. 운행을 마치면 `TripLedger`가 계기판 원본과 분류 이력을 **해시 체인**으로 잇습니다(자세한 규칙은 `docs/integrity.md`).

질문이 오면: "상태 기계는 입력을 받아 다음 상태와 할 일만 돌려주는 순수 함수라서, 기어를 D→P→D로 바꾸는 상황을 테스트로 전부 확인했습니다(`TripStateMachineTest`)."

### 3-2. 정차 후 분류: 화면 한 번, 말 한마디, 또는 직접 입력

- 정차하면 `DriveLogRoot`가 분류 화면(`ClassificationScreen`)을 띄우고 무드등이 노란색으로 바뀝니다(`CabinAssistant`).
- 정차 안내를 읽은 뒤 `VoiceJournal`이 대화를 시작합니다.
  1. 묻기: "용도와 업무 내용을 말씀해 주세요"
  2. 듣기: `PleosListener`가 차 안 음성 인식 엔진으로 받아 적습니다. 엔진이 1초쯤 쉬면 끊어 버려서, 이어 말하면 이어 붙입니다.
  3. 해석: `SpokenTripParser`가 "업무, 거래처 납품 미팅"을 용도=일반업무, 업무 내용=거래처 납품 미팅으로 나눕니다.
  4. 확인: 들은 내용을 읽어 주고 "맞아"·"다음"이라고 하거나 [맞아요]를 누르면 기록합니다. 틀리면 다시 말하거나 [직접 입력]으로 씁니다.
- [나중에]를 누르면 듣기를 멈추고 **바로 하차 점검**을 합니다. 그 운행은 홈의 "분류하지 않은 운행" 배너에서 다시 엽니다.
- 다시 출발하면 듣기를 즉시 멈춥니다. 운전 중에는 묻지 않습니다.

### 3-3. 공용차 맞춤과 하차 점검

- 운전자를 고르면 `DriverProfiles`가 그 사람의 온도·시트 열선·무드등을 `PleosCabinControl`로 맞추고, 운행기록부 사용자 칸에 이름을 적습니다. 운행이 끝나면 그때 설정을 다시 기억합니다.
- 운행이 끝나거나 [나중에]를 누르면 `CabinAssistant`가 창문·실내등·문 잠김·배터리를 읽어 '내리기 전에 확인해 주세요' 카드와 소리로 알립니다.
- 차 상태 화면(`CarStatusScreen`)은 5초마다 다시 읽어 차 그림 위에 열린 창문을 보여 줍니다.

### 3-4. 서버로 올리기와 회사 연결

- 차는 비밀번호 없이 **익명 로그인**(`DeviceAuth`)을 하고, 관리자가 준 6자리 코드로 회사에 등록합니다(`pair_vehicle` 함수).
- `SyncScheduler`는 올릴 기록이 생기고 인터넷이 연결되면 `SyncRepository`를 부릅니다. 실패하면 간격을 늘려 다시 시도하고, 15분마다 한 번 더 확인합니다.
- 서버는 앱이 만든 id로 덮어쓰므로 같은 기록을 여러 번 올려도 중복되지 않습니다.
- 앱에는 공개 키(anon)만 들어갑니다. 무엇을 읽고 쓸 수 있는지는 서버의 표 권한(RLS)과 함수가 정합니다.

### 3-5. 휴대폰으로 받기

차에는 메일 앱이 없어서, 운행기록부 화면에서 QR 코드를 만듭니다. 서버 함수 `create_share_link`가 **10분짜리 주소**를 만들고(한 시간에 20개까지), 휴대폰은 `web/`의 공유 페이지에서 CSV·PDF로 받습니다.

### 3-6. 도움 비서와 사용법

- 처음 실행하면 사용법 4장(`TutorialScreen`)을 소리와 함께 보여 줍니다. 설정의 [사용법 다시 보기]로 다시 엽니다.
- 홈 오른쪽 위 물음표 버튼을 누르면 `HelpAssistant`가 묻고 듣습니다. "차 상태 알려 줘"처럼 말하면 낱말 규칙(`HelpIntentParser`)으로 일곱 가지 주제 중 하나를 고르고, 답을 읽은 뒤 그 화면으로 데려갑니다. 인터넷이나 외부 AI를 쓰지 않습니다.
- 출발하거나 분류 화면이 뜨면 도움 창은 닫힙니다(마이크를 운행 분류와 같이 쓰지 않게).

## 4. 안전 원칙 (심사에서 자주 물어볼 부분)

1. **운전 중에는 화면을 만질 일이 없다.** 주행 제한(`CarUxRestrictions`)이 걸리면 주행 화면만 보여 주고 다른 화면·창은 모두 닫습니다.
2. **창문·문·실내등은 P이고 주행 제한이 없을 때, 운전자가 직접 누를 때만** 움직입니다(`CabinAssistant.safeToControl`). 기어를 읽지 못해도 움직이지 않는 쪽으로 판단합니다.
3. **바꾼 뒤 다시 읽어 확인합니다.** 차가 받아들이지 않은 항목은 "직접 확인해 주세요"로 남깁니다.
4. **소리 안내와 음성 인식은 차 안 엔진만** 씁니다. 목소리와 문장이 차 밖으로 나가지 않습니다.

## 5. 개인정보와 보안

- 차 안 DB는 SQLCipher로 암호화하고, 열쇠는 안드로이드 Keystore로 지킵니다. 설정 값도 암호화해 저장합니다.
- 실시간 위치는 저장하지 않습니다. 운행 시작·끝 두 시점의 주소만 씁니다.
- 비업무로 분류하면 주소·도착 정보·업무 내용을 바로 지우고 거리만 남깁니다. 해시 체인에는 주소를 넣지 않아서 지워도 체인이 깨지지 않습니다.
- 서버 관리자 키(service_role)와 비밀값은 앱과 웹 어디에도 없습니다. 비밀값은 커밋하지 않는 `backend/.env`에만 둡니다.
- 동의를 철회하면 차 안 기록과 설정을 모두 지우고 서버 연결도 끊습니다.

## 6. 테스트

- 단위 테스트 192개(`app/src/test`). 상태 기계, 기록부 계산, 해시 체인 검증, 동기화, 말 해석, 음성 대화 흐름, 도움 비서, 차 점검을 차 없이 확인합니다.
- 실행: `./gradlew :app:testDebugUnitTest` (JDK 17)
- 화면과 차량 연동은 Pleos Connect 에뮬레이터와 Virtual Console로 확인합니다(README "테스트 환경").

## 7. 예상 질문과 답

| 질문 | 답 |
|---|---|
| 운행 시작과 끝은 어떻게 아나요? | 기어입니다. P에서 벗어나면 시작, P에 두면 정차, 정차 중 용도를 고르거나 5분이 지나면 끝입니다. 신호 대기는 D 그대로라 정차로 치지 않습니다. |
| 앱이 꺼지면 기록이 사라지나요? | 아닙니다. 상태가 바뀔 때마다 바로 저장하고, 포그라운드 서비스로 화면이 꺼져도 돌며, 부팅하면 다시 시작합니다. |
| 인터넷이 끊기면요? | 기록·분류·운행기록부는 차 안에서 그대로 됩니다. 연결되면 나중에 올립니다. |
| 기록을 누가 고치면요? | 계기판 원본과 분류 이력을 해시 체인으로 묶어서, 값을 바꾸거나 지우면 운행기록부에 흔적이 보입니다. |
| 음성 인식이 틀리면요? | 기록하기 전에 들은 내용을 읽어 주고 확인받습니다. 틀리면 다시 말하거나, 버튼을 누르거나, 직접 씁니다. |
| Gleo AI 음성 명령은요? | 향후 계획입니다. 공모전 참가팀은 Gleo Interface 검토·승인을 신청할 수 없어, 스키마와 처리 코드만 준비해 두고 출품 기능에는 쓰지 않았습니다. 말로 기록은 앱이 SpeechToText로 직접 듣기 때문에 그것 없이도 됩니다. |
| 운전 중에 창문이 움직일 수 있나요? | 없습니다. P이고 주행 제한이 없을 때, 운전자가 직접 누를 때만 움직이도록 코드에서 막았습니다. |
| 다른 회사 기록이 보일 수 있나요? | 서버 표 권한(RLS)으로 자기 회사 기록만 읽게 했고, 앱에는 공개 키만 들어 있습니다. |
| 감시 도구가 되지 않나요? | 실시간 위치를 저장하지 않고, 비업무 운행은 주소를 지우고 거리만 남깁니다. |
| 왜 서버로 Supabase를 썼나요? | Pleos 에뮬레이터에는 구글 서비스(GMS)가 없어 Firebase를 쓸 수 없습니다. Supabase는 일반 HTTPS라 그대로 됩니다. |
