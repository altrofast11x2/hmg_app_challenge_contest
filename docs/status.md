# 구현 현황

> 마지막 갱신: 2026-10-26 · 표기: **완료**(구현하고 확인함) / **진행 중**(구현했지만 확인이 남음, 또는 일부만 구현) / **계획**(아직 구현하지 않음)
> 공모전 규정에 따라 확인하지 않은 기능을 완료로 적지 않는다. "확인" 칸에 무엇으로 확인했는지 적는다.

| 기능 | 상태 | 확인 |
|---|---|---|
| 기어로 운행 시작(P 아님)·정차(P) 자동 감지 | 완료 | 에뮬레이터 + Virtual Console, 상태 머신 단위 테스트 |
| 주행 전·후 계기판 거리 자동 기입 (Vehicle SDK Odometer) | 완료 | Virtual Console 거리 변경이 기록에 반영 |
| 주행 중 조작 0 (터치 요소 없는 주행 화면, `distractionOptimized`) | 완료 | D에서 주행 화면으로 바뀌고 터치 요소 없음 |
| 정차 후 원탭 분류 (출퇴근 / 일반업무 / 비업무 / 나중에) | 완료 | 에뮬레이터 |
| 같은 목적지는 지난번 분류를 기본값으로 제안 | 완료 | 단위 테스트 |

| 앱이 강제 종료돼도 진행 중인 운행 복원 | 완료 | 에뮬레이터에서 강제 종료 후 확인 |
| 운행 시작·종료 주소 (NaviHelper) | 완료 | 에뮬레이터에서 주소 수신 확인 |

| 비업무 운행은 주소·방문처를 지우고 거리만 남김 | 완료 | 단위 테스트 |

| 연비·전비 | 진행 중 | 코드 완료. 에뮬레이터 미지원이라 실제 값은 확인 못 함 |
| 차량 식별(VIN). 없으면 앱이 만든 기기 ID | 진행 중 | 기기 ID 대체는 확인. 에뮬레이터 VIN이 "invalid"라 실제 VIN은 확인 못 함 |
| 월별 운행기록부 (국세청 업무용승용차 운행기록부 서식 열), 월 요약, 미분류 나중 분류 | 완료 | 에뮬레이터, 단위 테스트 |

## M1 · 계정과 서버

| 기능 | 상태 | 확인 |
|---|---|---|
| 서버(Supabase) 스키마, 권한(RLS: 관리자·운전자, 열람자 구조만), 연결 코드 함수 | 완료 | 원격 프로젝트에 적용, Supabase 보안 점검, 관리자 계정으로 실제 API 확인 |
| 데모 기업·기업 관리자 계정·개발자 계정·시연용 연결 코드 (`backend/seed/`) | 완료 | 원격 프로젝트에 생성, 두 계정 웹 로그인 확인 |
| 차량 연결 (정차 중 6자리 코드 입력) | 완료 | 에뮬레이터 release 앱에서 시연용 코드로 데모 기업에 연결, 서버에 차량·기본 운전자 등록 확인 (2026-10-26) |
| 오프라인 우선 동기화 (재시도, 중복 방지) | 완료 | 운행 3건(일반업무·비업무·미분류)과 분류 이력이 서버에 올라감, 비업무 주소 삭제·해시 체인 1~6 확인, 단위 테스트 |
| 관리자 웹: 로그인, 운행기록부(달 바로 고르기, 날짜로 기간 고르기)·CSV, 차량 목록·연결 해제, 연결 코드 발급 | 완료 | https://altrostudio-drivelog.vercel.app 배포, 기업 계정으로 실제 운행 3건 표시 확인, 앱과 같은 디자인 토큰 |
| 개발자 계정: 기업 정보 입력·기업 등록(기업 관리자 계정 생성) | 완료 | 관리자 웹 개발자 화면, 권한 시험(기업 계정은 거부, 새 기업 관리자는 자기 기업만) |
| 관리자가 운전자 추가 | 계획 | 서버 권한만 있고 웹 화면 없음 |
| 운전자가 웹에서 자기 기록 열람 | 계획 | 서버 권한만 있음. 차 안에서는 월별 운행기록부로 열람 가능 |
| 서버 일시 정지 방지 (Supabase 무료 플랜 7일 비활성) | 완료 | GitHub Actions가 하루 두 번 조회. 저장소 Secrets 등록 후 수동 실행에서 HTTP 200 확인 (2026-10-27) |
